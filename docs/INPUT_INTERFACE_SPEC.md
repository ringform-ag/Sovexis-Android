## 第二章：安全级别定义

### P0 核心

**定义**：涉及密钥材料、身份创建、主权存储访问的操作。必须通过生物认证或多因素验证。

**触发操作示例**：
1. 主账号创建/解锁 → 必须生物认证
2. TSS 密钥份额解密 → 必须生物认证 + 多宫格密码
3. L2 存储（Path ORAM）映射表恢复 → 必须生物认证 + 真假混淆

---

### P1 高优

**定义**：涉及支付确认、凭证签发、BLE 配对的操作。需用户在场确认。

**触发操作示例**：
1. 支付确认 → 需要用户确认金额和收款方
2. TSS 签名（标准模式）→ 需要 BLE 配对确认
3. 凭证签发 → 需要用户授权

---

### P2 可选

**定义**：日常配置修改、笔记编辑。低风险，可简化验证。

**触发操作示例**：
1. 保险箱笔记编辑（L0/L1）→ 简化验证即可
2. 隐私策略开关 → 可选混淆
3. 通知偏好设置 → 无需验证

---

## 第三章：高风险场景定义

### 高风险场景判定条件

高风险场景需要触发"真假混淆弹窗"介入。

---

#### 场景 1：TSS 高安全模式签名

**触发条件**：
- 用户发起 TSS 签名请求
- 当前为高安全模式（TSS_SECURE_HIGH）
- 签名涉及密钥份额访问

**对应的输入接口**：
- 生物认证 (BiometricPrompt)
- 多宫格密码 (KDFS Pattern)
- 真假混淆入口（必须触发）

---

#### 场景 2：L2 主权存储（Path ORAM）的映射表恢复操作

**触发条件**：
- 用户请求恢复 L2 存储的映射表
- 映射表包含所有数据项的位置信息
- 泄露可导致访问模式分析

**对应的输入接口**：
- 生物认证 (BiometricPrompt)
- 真假混淆入口（必须触发）

---

#### 场景 3：主账号恢复流程

**触发条件**：
- 用户使用助记词发起主账号恢复
- 恢复过程涉及大量密钥派生
- 助记词已暴露于输入框

**对应的输入接口**：
- 助记词输入
- 真假混淆入口（必须触发）

---

#### 场景 4：设备被标记为 RISK_ROOTED 后的所有 P0 操作

**触发条件**：
- 设备安全状态为 RISK_ROOTED
- 用户发起任何 P0 核心操作

**对应的输入接口**：
- 生物认证 (BiometricPrompt) + Root 警告弹窗
- 真假混淆入口（建议触发）

---

## 第四章：真假混淆交互逻辑

> **重要说明**：本章只写交互逻辑，不写具体 UI 呈现。弹窗文案、按钮样式、轮次选择器由 ringform 主导设计。

### 核心机制

真假混淆不是软件层自动伪造。在高风险场景下，系统弹窗提醒用户"当前为高风险操作"。

用户自己决定走一套真输入、一套或多套假输入。**所有输入都是用户真实操作**，攻击者无法从系统行为区分。只有用户自己知道哪一套是真。

---

### 交互流程

#### 步骤 1：触发

用户发起高风险操作（如 TSS 签名）

#### 步骤 2：弹窗提示

系统显示高风险操作提示弹窗，告知：
- 当前为高风险操作
- "为保护您的隐私，请进行多轮输入，其中只有一轮是真实有效的"
- 用户可选择：
  - "仅输入一轮"（不使用混淆）
  - "输入两轮"（启用混淆）
  - "取消操作"

#### 步骤 3：第一轮输入

用户进行第一轮输入，**由用户自行决定这一轮是真还是假**。

#### 步骤 4：第二轮输入（如选择混淆）

用户进行第二轮输入，**由用户自行决定这一轮是真还是假（与第一轮不同）**。

#### 步骤 5：系统处理

- 两轮输入都进入正常的处理流程
- 只有用户自己知道哪一轮是真
- 攻击者即使监控所有系统调用，也只能看到两轮合法输入

#### 步骤 6：结果返回

Sovexis 内部仅使用用户认为"真"的那一轮结果

---

### 关键约束

| 约束 | 说明 |
|------|------|
| 系统不指定真假 | 系统不指定哪轮是真哪轮是假 |
| 不存储真假标记 | 系统不存储任何真假标记 |
| 暂停限制 | 每轮输入之间允许用户暂停（最长 30 秒） |
| 超时处理 | 超时则本次高风险操作取消，需重新发起 |

---

### 留白

以下内容由 ringform 主导设计：
- 具体的弹窗文案
- 按钮样式
- 输入轮次选择器
- 暂停超时提示样式

## 第五章：各输入接口规格

---

### 5.1 生物认证 (BiometricPrompt)

| 属性 | 说明 |
|------|------|
| 所属模块 | 身份 |
| 输入类型 | 生物（指纹/面部） |
| 验证方式 | 本地（Android BiometricPrompt API） |
| 错误处理 | 失败时重试，最多 3 次；3 次失败后锁定 30 秒 |
| 超时时间 | 60 秒 |
| 关联 ZKP 因素 | 强因子 |

**安全约束**：
- 必须使用 `BiometricPrompt.PromptInfo` 配置 `setNegativeButtonText`
- 必须验证 `BiometricPrompt.AuthenticationCallback` 的 `authenticationError`
- 禁止在回调外处理生物数据

**留白**：UI 样式、认证失败动画 [待 ringform 主导设计]

---

### 5.2 多宫格密码 (KDFS Pattern)

| 属性 | 说明 |
|------|------|
| 所属模块 | 身份 / TSS |
| 输入类型 | 图案（4×4 宫格） |
| 验证方式 | 本地 |
| 错误处理 | 失败时重试，最多 5 次；5 次失败后触发冷却期（5 分钟） |
| 超时时间 | 120 秒 |
| 关联 ZKP 因素 | 强因子 |

**额外要求**：
- 宫格规模：默认 4×4
- 最小连接点数：6
- 确认方式：必须绘制两次，两次一致才能确认
- 用途说明：作为 HKDF 的 info 参数参与密钥派生，不直接作为解锁密码

**留白**：UI 样式、连接线动画 [待 ringform 主导设计]

**重置机制**：待定 [待 ringform 后续主导设计]

## 第六章：安全约束

### 强制约束

| 约束 | 为什么需要这个规则 |
|------|-------------------|
| 禁止日志记录：任何输入接口的明文内容不得写入 Logcat 或任何日志文件 | 防止攻击者通过日志提取敏感输入 |
| 禁止屏幕录制：所有 P0 和 P1 级别的输入页面必须设置 FLAG_SECURE | 防止录屏攻击获取输入内容 |
| 内存清理：输入完成后，包含明文数据的 ByteArray 和 String 必须立即覆写 | 防止内存转储攻击提取残留数据 |
| Root 设备警告：若设备标签为 RISK_ROOTED，所有 P0 输入接口需在弹窗中追加风险提示 | 警告用户当前环境不安全 |
| 超时处理：所有需要用户输入的操作必须有超时限制，超时后清除所有中间状态 | 防止攻击者利用未清理的会话状态 |
| 防暴力破解：关键输入（多宫格密码，助记词）在连续失败 N 次后触发冷却期 | 防止暴力破解攻击 |

### 建议约束

| 约束 | 为什么建议 |
|------|------------|
| 混淆输入延迟：真假混淆时，可在两轮输入之间加入随机延迟 | 增加攻击者时间线分析难度 |
| 电池优化白名单：P0 输入操作期间禁止系统进入低电耗模式 | 确保生物认证流程不被中断 |
