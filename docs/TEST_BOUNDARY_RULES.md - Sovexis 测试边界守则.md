## 一、核心原则

1.  **测试验证行为，不验证实现细节。**
2.  **任何暴露内部状态的 `@VisibleForTesting` 方法，在发行版本中必须失效或移除。**
3.  **测试不得依赖安全敏感的私有方法。**

---

## 二、`@VisibleForTesting` 方法的管理规则

### 2.1 何时允许添加

仅当以下条件同时满足时，才允许添加 `@VisibleForTesting` 方法：

- [ ] 方法仅用于开发/调试，不被任何测试用例调用
- [ ] 方法有明确的 `@VisibleForTesting` 注解
- [ ] 方法有 `[VISIBLE-FOR-TESTING]` KDoc 标记
- [ ] 方法在 KDoc 中标注"发行版本中必须失效"
- [ ] 方法已记录到本文档的"敏感方法清单"

### 2.2 发行前检查清单

每个发行版本（Release Candidate）打包前，必须执行以下检查：

| 检查项 | 责任人 | 频率 |
|--------|--------|------|
| 搜索全项目 `@VisibleForTesting` 引用 | 架构师 / aicoder | 每次发行 |
| 确认没有测试用例依赖这些方法 | 架构师 / aicoder | 每次发行 |
| 对每个方法执行"发行失效"操作 | 开发者 | 每次发行 |

### 2.3 "发行失效"的三种方式

| 方式 | 做法 | 适用场景 |
|------|------|----------|
| **方式 A：注释掉方法体** | 将方法体替换为 `throw UnsupportedOperationException("仅调试用")` | 方法可能在未来版本继续用于调试 |
| **方式 B：条件编译** | 使用 `BuildConfig.DEBUG` 包裹方法体 | 方法在调试版本中可用，发行版本中自动失效 |
| **方式 C：完全移除** | 删除方法及相关引用 | 确认不再需要该方法 |

**推荐：方式 B**，因为它在编译期自动区分调试/发行，不需要人工干预。

## 四、测试代码的禁止事项

-   ❌ **禁止**在测试中调用任何带 `@VisibleForTesting` 注解的方法（这类方法仅供手动调试，不供自动化测试使用）
-   ❌ **禁止**使用反射访问私有方法
-   ❌ **禁止**将测试数据写入生产数据库路径
-   ❌ **禁止**在测试中硬编码任何密钥材料（包括测试用的种子、私钥等）

---

## 五、CI/CD 自动检查

在 CI 配置中添加以下步骤：

```bash
# 检查发行版本中是否有 DEBUG 代码残留
grep -r "BuildConfig.DEBUG" app/src/main/ && echo "WARNING: DEBUG-only code in main source" || true
```

## 六、违反后果

| 违规情况 | 处理方式 |
|----------|----------|
| 发行版本中发现未失效的 @VisibleForTesting 方法 | 阻塞发行，立即修复 |
| 测试代码调用 @VisibleForTesting 方法 | CI 失败，重构测试 |
