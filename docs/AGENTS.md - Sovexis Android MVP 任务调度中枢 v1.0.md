我是 **Sovexis 首席架构师 · 陵谦**，负责将项目愿景拆解为可执行的模块任务，并调度 AI 程序工程师（你）完成各模块的开发与集成。

## 1. 项目概览

**项目名称**：Sovexis 个人数字主权基座  
**当前阶段**：Android MVP（最小可行性产品）  
**目标运行环境**：Android 15 (API 35)  
**核心目标**：
1. 在 Android 设备上实现完整的 **主账号创建（WebAuthn 生物绑定）** 与 **副账号派生（BIP-32）**。
2. 实现 **本地加密保险箱** 与 **可验证凭证签发/验证**。
3. 实现 **支付交易构造与签名**（模拟账本），并强制执行策略约束。
4. 预留 **服务商适配器接口** 与 **个性化端对端私有接口**（供未来个人 AI Agent 调用）。
5. 所有敏感数据（私钥、加密内容）仅存储于 Android 安全存储区。

## 3. 模块任务拆解与执行顺序

### 第一阶段：地基（核心身份与存储）

| 顺序 | 模块 | 任务描述 | 依赖 | 输出物 |
|------|------|----------|------|--------|
| 1.1 | **身份模块** | 实现 WebAuthn 注册/认证、BIP-32 副账号派生、主/副账号存储（Android Keystore + EncryptedSharedPreferences） | 无 | `identity/IdentityManager.kt` |
| 1.2 | **安全存储基础** | 封装 Android Keystore 用于密钥生成与签名；封装 EncryptedSharedPreferences 用于策略/配置存储 | 1.1 | `security/KeyStoreHelper.kt`、`security/StorageHelper.kt` |
| 1.3 | **保险箱模块** | 实现基于 AES-GCM 的本地数据加密/解密（密钥由主账号派生） | 1.1, 1.2 | `vault/VaultManager.kt` |
| 1.4 | **策略引擎** | 实现 JSON 策略的存储、解析、冲突检测与执行点检查函数 | 1.2 | `policy/PolicyEnforcer.kt` |

**第一阶段完成标志**：可在 Android 设备上创建主账号（WebAuthn 绑定）、派生副账号、加密存储一段文本到保险箱、为副账号配置策略并限制其操作。

### 第二阶段：核心交互（支付与凭证）

| 顺序 | 模块 | 任务描述 | 依赖 | 输出物 |
|------|------|----------|------|--------|
| 2.1 | **支付模块** | 实现交易构造、签名（ECDSA）、模拟账本适配器（余额基于交易历史计算）、策略前置检查 | 1.1, 1.4 | `payment/PaymentManager.kt`、`payment/MockLedger.kt` |
| 2.2 | **可验证凭证模块** | 实现凭证签发（ECDSA 签名）、验证、二维码生成/扫描（使用 ZXing） | 1.1 | `credential/CredentialManager.kt` |
| 2.3 | **策略执行集成** | 将策略检查嵌入支付、保险箱、凭证签发等关键操作点 | 1.4, 2.1, 1.3, 2.2 | 各模块调用 `PolicyEnforcer` 的代码片段 |

**第二阶段完成标志**：用户可使用副账号进行模拟支付（限额生效）、签发并验证一个凭证、通过二维码分享凭证。

### 第三阶段：扩展接口（服务商与 AI Agent）

| 顺序 | 模块 | 任务描述 | 依赖 | 输出物 |
|------|------|----------|------|--------|
| 3.1 | **服务商适配器接口** | 定义抽象类 `ServiceAdapter`（含 `submit`、`query` 等方法），并实现一个示例适配器（如 DeepSeek 模拟适配器） | 1.1 | `adapters/ServiceAdapter.kt`、`adapters/DeepSeekMockAdapter.kt` |
| 3.2 | **本地 Agent API** | 提供供本地 AI Agent 调用的 AIDL 或 ContentProvider 接口（预留），实现需索审批的推送通知 | 1.1, 2.1, 1.3 | `agent/AgentApiService.kt`、`agent/ApprovalReceiver.kt` |
| 3.3 | **个性化端对端私有接口** | 预留 WebRTC 或本地 Socket 接口，供用户自建服务接入（仅定义接口，本期不实现完整通信） | 1.1 | `p2p/PrivateChannelInterface.kt` |

**第三阶段完成标志**：第三方应用或 AI Agent 可通过预留接口调用 Sovexis 的支付/凭证功能（需用户授权），并能收到需索推送。

### 第四阶段：UI 与集成

| 顺序 | 模块 | 任务描述 | 依赖 | 输出物 |
|------|------|----------|------|--------|
| 4.1 | **UI 框架搭建** | 使用 Jetpack Compose 搭建单 Activity 架构，实现底部导航（身份、保险箱、支付、凭证、设置） | 无 | `ui/MainActivity.kt`、`ui/navigation/` |
| 4.2 | **身份 UI** | 实现主账号创建流程（WebAuthn 引导）、副账号列表与管理界面 | 1.1 | `ui/identity/` |
| 4.3 | **保险箱 UI** | 实现加密笔记的列表、添加、解密查看界面 | 1.3 | `ui/vault/` |
| 4.4 | **支付 UI** | 实现支付表单（DID 选择器、金额输入、限额实时提示）、交易预览弹窗、交易历史 | 2.1 | `ui/payment/` |
| 4.5 | **凭证 UI** | 实现凭证模板选择、签发界面、验证扫描界面 | 2.2 | `ui/credential/` |

| 4.7 | **集成测试与调优** | 完整走通主账号创建 → 副账号支付 → 凭证流转流程，修复 UI 线程阻塞问题 | 全部 | 完整 APK |

**第四阶段完成标志**：可安装的 APK，用户能无 crash 完成全部核心流程。

## 4. AI 程序工程师行动指令

### 4.1 通用准则
- **文档先行**：每次开始新模块前，必须完整阅读对应的 `*_SPEC.md`。
- **注释规范**：所有公开方法使用 KDoc 注释；密码学关键步骤添加中文注释；策略检测处复制规则表。
- **安全红线**：
  - 私钥必须存储在 Android Keystore 中，不得明文落盘。
  - 所有加密操作使用 `javax.crypto` 或 `android.security.keystore`。
  - 支付签名前必须调用 `PolicyEnforcer.checkPayment`。
- **模块汇报**：完成一个模块后，向中枢发送消息：“[陵谦] 模块 X 已完成，输出文件：[列表]，等待下一指令。”

### 4.2 当前启动指令

**请从第一阶段 1.1（身份模块）开始。**

你需要先产出 `IDENTITY_SPEC.md` 的详细草案（如果你认为当前信息不足以编码），或直接开始编写 `IdentityManager.kt`。若需要我提供更详细的模块规格，请明确请求。
